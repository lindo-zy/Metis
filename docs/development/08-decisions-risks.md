# 08 · 设计决策、风险与未决事项

## 1. 已固定的默认设计

| ADR | 决策 | 理由与边界 |
| --- | --- | --- |
| 001 | 一个包/一个设置入口/三个独立模块 | 用户集中管理，保留独立停用与故障定位 |
| 002 | 成熟核心迁入，壳与协作重新开发 | 避免算法/私有 API 全量重写的集中风险 |
| 003 | 运行二进制按进程拆分 | 不把截图和历史库注入所有 UIKit hosts |
| 004 | 保留原类名前缀，新增 MT 协议 | 移植 diff 可审查，不把改名噪声和行为修改混合 |
| 005 | Settings 为配置唯一写入者，runtime state 分离 | 避免三域同步回环与数组/排序覆盖 |
| 006 | 动作 UUID + 引用，内置能力固定 ID | 改名不坏引用；不依赖原 dylib 文件名 |
| 007 | 先窗口租约与 hook ownership，再考虑 UI 重构 | 保留现有窗口细节，先解决重复 hook 与模态冲突 |
| 008 | 旧入口单向兼容，新内部请求不走旧通知 | 减少重复执行、回环和外部插件误触 |
| 009 | 剪贴板写入统一，自动协作默认关闭 | 集成不应默默增加历史记录或数据发送 |
| 010 | 配置备份与私密历史备份分开 | 用户能理解导出内容和恢复范围 |
| 011 | v1 统一外部 AltList 依赖 | 先消除 vendored 与外部副本重名，后续可单独评估内置化 |
| 012 | 默认本地构建，发布动作独立 | 避免继承源构建脚本的个人云/通知副作用 |
| 013 | 旧库只读复制，schema 在副本升级 | 不让 Metis 试验性迁移损坏原插件回滚路径 |
| 014 | 新装模块默认关，导入后显式启用 | 空配置不等于同意截图/键盘 hook/剪贴板采集 |

实现者可提出改变，但应先写 ADR：问题、证据、替代方案、配置/迁移/测试影响、接受标准；不能只在代码里悄悄改变以上决策。

## 3. 需要实际原型/决策的事项

这些是实施任务，当前不阻止写手册。由任务负责人用证据解决；只有真正改变用户范围/数据删除等行为时再请求用户决策，不能每一步都停下来征求例行实现许可。

1. **许可与分发范围**：TypeX AGPL、Kayoko GPL 文件已登记，PixPin 未发现根许可；保存来源与 notice，发布前确定可分发策略。不在本手册作法律结论。
2. **RootHide IPC 与权限**：新只读快照、配置写入、私密凭据访问、App/键盘 appex 通道要最小原型；未经验证不能照搬旧 0777 共享方案。
3. **私有 API 能力**：具体系统小版本、悬浮 Scene/跨进程触摸、系统控件、粘贴提示 hook 需要设备能力表；缺失时只停相关能力。
4. **旧包替换顺序**：审查原安装/卸载脚本与包管理器冲突流程，明确导出发生在数据可能被清理之前。
5. **外部兼容边界**：保留已记录 public 入口；第三方未公开类/方法需独立 adapter 和可用性检测，不纳入核心硬依赖。
6. **性能预算**：第一轮设备基线后固定数值阈值；没有测量时只能给测量计划。
7. **产品名/图标**：当前使用 Metis 主品牌 + 原模块名，沿用可用源图标须登记来源；无授权来源的新视觉再单独设计。

## 4. 不作为 v1 默认目标的事项

- 不增加模块在线下载、运行时代码插件市场、账号系统或云同步服务。
- 不让三个旧插件与新 Metis 并行注入做长期双写/双向配置同步。
- 不把“统一管理”扩展成删掉三个模块的原功能，也不要求所有运行面板长得相同。
- 不以“合并”为由自动启用全局手势、自动传 AI、记录 OTP 或导入其他 App 数据。
- 不把删除旧库、推送 Git、发布/云上传、USB/SSH 当普通源码开发的隐含步骤。

若用户明确提出上述新范围，更新本手册和任务图再开发，保留原需求的可追溯性。
